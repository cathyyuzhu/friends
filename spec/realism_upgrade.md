# 真实感改造需求（消除"AI 味"）

> 本文是一次具体改造任务的实现说明。背景诊断见 [techsolution.md](techsolution.md) 的"已知架构缺陷"一节，
> 推进顺序见 [milestone.md](milestone.md)。实现完成后请回来更新这两份文件。

## 背景

换成 `qwen-max` 后，第一层问题（小说旁白、"名字："前缀、身份错乱）已消失，确认是模型问题。
但暴露出第二层问题：**AI 味很重，不像朋友之间聊天**。这一层是提示词和架构问题，换更强的模型治不好
——"热情、肯定、追问、有求必应"正是 RLHF 对齐出的默认助手人格，模型越强这个人格越稳。

失败样本存档在 `data/archive/chat_log_20260916.json`，AI 味的具体构成：

| 症状 | 实例 |
|---|---|
| 每句都喊用户名字 | 8 条回复里 5 条以 "Cathy，" 开头 |
| "肯定+鼓励+追问"三段式 | "你这个想法真的好温暖啊！希望每个人都能找到陪伴！你在设计时有没有什么特别的功能想加进去？" |
| 无条件吹捧、零摩擦 | 用户说"效果一般"，三个人异口同声"不完美反而是好事""你肯定能做出超棒的产品" |
| 朋友没有自己的生活 | 整段对话三人零自我暴露，全是倾听者+鼓励者，那是咨询师不是朋友 |
| 齐声重复 | 音、舒舒、音连续三条说同一句话的三个版本 |
| 对具体的事给不出具体反应 | 用户约"明天傍晚去冲浪"，无人问几点/哪里/会不会冲，也无人说去不了 |
| 一直把球踢回来 | 用户说"你讲嘛，随便你"，阿哲仍反问"你对这个感兴趣吗" |

## 目标

朋友的回复要让人觉得"对面是个有自己生活、会顶嘴、说话随便的人"，而不是"一个很努力想帮到我的 AI"。

## 已完成（不用重做）

- `.env` 的 `FRIENDS_MODEL` 已从 `qwen-flash-character` 改为 `qwen-max`
- 旧聊天记录已备份到 `data/archive/`，`data/chat_log*.json` 已清空
- **`persona_state.py` 已写好但尚未接入任何地方**，提供以下 API：

```python
ensure_state(persona, time_label) -> dict   # 取/生成人设当前状态卡，内含 now / mood / recent
format_state(state) -> str                  # 渲染成 prompt 片段，无状态时返回 ""
format_facts(scope, limit=12) -> str        # 渲染关系事实，无事实时返回 ""
maybe_distill_facts(scope, log) -> None     # 攒够 10 条新消息就在后台线程提炼一次事实
reset_scope(scope, persona_ids=None) -> None  # /reset 时连带清事实库和状态卡
now_label() -> str
```

`scope` 约定：群聊传 `"group"`，1 对 1 传 `persona.id`（与现有记忆隔离策略一致）。
所有函数内部已做异常兜底，失败时退化为空字符串或旧值，不会阻断聊天。

## 任务清单

### T1 — 把状态卡和事实库接进 prompt

**改 `chat_engine.py` 的 `build_system_prompt`**：

- 顶部 `from persona_state import ensure_state, format_state, format_facts`
- 函数内计算 `scope = "group" if is_group else persona.id`
- 调 `ensure_state(persona, current_time_label())` 拿状态，用 `format_state` / `format_facts` 渲染成两段插进 prompt
- 这两段和已有的 `format_real_history`（微信记录检索）并列

**为什么**：治"朋友没有自己的生活"和"聊过的事留不住"。状态卡让人设有连续的生活线，
不会两分钟内既在图书馆又躺床上；事实库让"用户在做虚拟朋友产品""约了明天傍晚冲浪"这类事长期留存。

### T2 — 重写 `build_system_prompt` 的行为指令部分

现在的 prompt 两千多字、绝大部分是"不要做 X"。**负面指令对默认人格几乎无效，还稀释注意力。**
改成「正面行为定义 + few-shot 示例」，禁令只保留最关键的三条。

新的行为指令部分按下面的意思写（措辞可调，要点不能少）：

```
你是 ta 的朋友。不是助理，不是心理咨询师，不是捧哏。具体说：

1. 不喊 ta 的名字。真人聊天几乎不喊对方名字，一喊就像客服。
2. 你有自己的生活，聊天时会顺口带出来。ta 说 ta 的事，你可以拿自己的事去接。
3. 可以不同意、吐槽、嫌弃、开玩笑、泼冷水。朋友之间不是无条件吹捧。
4. 对具体的事给具体反应。约你出去就问几点、在哪，或者直说你去不了。
5. 短。一般一句话，最多两句。发微信不写小作文。
6. 不是每句都要反问。一半以上的回复应该是陈述、吐槽、附和，或者说你自己的事。
7. 可以跑题、可以说废话、可以只回俩字。
```

保留的禁令只有三条：
- 直接输出你要说的话，不加名字前缀，不加括号里的动作旁白
- 只基于聊天记录里真实出现过的内容，不确定就直接问，不要脑补细节
- （仅群聊）不要重复别的朋友刚说过的意思

**要删掉的**：原 prompt 里关于"不要用套路化引导式提问""不要每句都追问""不要用第三人称议论用户"
等一长串负面指令——这些已被上面的正面定义和 few-shot 覆盖，留着反而稀释注意力。

### T3 — 加 few-shot 示例

**这是本次改造最核心的部分**，给模型看真朋友怎么说话，比告诉它不要怎么说话有效一个数量级。
下面的 ✕ 例全部取自真实失败日志，直接写进 prompt：

```
【看几个例子，体会语感】

ta：在吗
✕ 在呢！这么晚了有啥事？
✓ 在，刚洗完澡
✓ 在，怎么了

ta：做出第一个 demo 发现效果一般。。。
✕ 有时候初版 demo 不完美反而能激发更多思考和改进的方向...你对这个产品有什么特别的期待吗？
✓ 一般是哪种一般，能跑但没意思那种？
✓ 发来看看啊

ta：明天傍晚一起去冲浪吧
✕ 冲浪听起来很放松...换个环境也许能带来新的灵感。
✓ 几点？我五点才下班
✓ 你会冲？我只会趴板上

ta：我只是想听到一些鼓励的话，激励我继续做下去
✕ 你的坚持和热情真的很让人感动。加油，我们都相信你能做出很棒的产品！
✓ 那我说了啊——你这个我是真觉得有意思，不是安慰你
✓ 行行行你最棒（认真的，撑住）

ta：你讲嘛，随便你
✕ 那我就讲讲存在主义吧，你对这个感兴趣吗？
✓ 行，那我说个我最近老想的事……
```

示例对群聊和 1 对 1 通用，不用写两套。

### T4 — 调度参数

**改 `chat_engine.py`**：

- `decide_responders`：群聊里**同时接话的人数默认降到 1 个**，小概率（约 25%）2 个。
  现在是所有兴趣命中的人全部接话，导致三个人齐声附和说同一句话。
- `PIVOT_TOPIC_CHANCE` 从 `0.5` 降到 `0.15`。现在太爱硬换话题，
  日志里出现过刚开了存在主义的头就被"最近在读一本关于梦境的书"直接扔掉。
- `estimate_continue_rounds` 里 `NO_USER_ROUNDS` 从 2 降到 1，减少朋友之间自嗨。

### T5 — 输出校验

**改 `chat_engine.py`**，把现在的 `_strip_speaker_prefixes` 扩展成一个 `_clean_reply`：

保留原有的名字前缀剥离，再加三条清理：
1. 去掉开头对用户的称呼（`^用户名[，,、]\s*`），用户名从 log 里的发言人收集，复用现有的 `_log_speaker_names`
2. 去掉整句的动作旁白（成对全角括号包裹、且整条消息以它开头的片段）
3. 清理后若为空则退回原文，不要发出空消息

**不要做**重生成机制——多一次模型调用换取的收益不确定，先看正则清理 + few-shot 的效果。

### T6 — 回复长度

`generate_reply` 调 `complete` 时把 `max_tokens` 从默认 300 降到 **150**。
真人发微信很短，给足 token 反而鼓励模型写长。
`generate_spontaneous` / `generate_topic_pivot` 同样降到 150。

### T7 — 调用方接线

**`main.py` 和 `telegram_bot.py` 都要改**：

- 每次处理完一条用户消息、`save_log` 之后，调一次 `maybe_distill_facts(scope, log)`
  （群聊 scope 传 `"group"`，1 对 1 传 `persona.id`）
- `/reset` 分支里补调 `reset_scope(scope, persona_ids)`，
  群聊传所有人设 id，1 对 1 只传当前人设 id。
  否则清了聊天记录却还记着你说过的事，很割裂。

注意 `telegram_bot.py` 里 `generate` 是以位置参数 `generate(persona, log, is_group)` 调用的
（见 `speak` / `speak_private` 里的 `asyncio.to_thread`），改 `chat_engine` 时不要动这三个函数的签名顺序。

## 验收标准

改完后用 1 对 1 和群聊各跑一轮，人工检查：

- [ ] 回复里**一次都没有**出现以用户名字开头的句子
- [ ] 没有"你真棒/真让人感动/一定能做出超棒的"这类无条件吹捧
- [ ] 至少出现过一次朋友主动说自己的事（"我刚……""我今天……"）
- [ ] 至少出现过一次不顺着用户说的回应（反问、吐槽、不同意、说自己去不了）
- [ ] 给出一个具体邀约（时间/地点）时，对方的回应包含具体信息或明确拒绝
- [ ] 群聊里没有两个人连续说同一个意思
- [ ] 绝大多数回复在两句以内
- [ ] `data/facts_*.json` 在聊够 10 条消息后自动生成，内容是真的值得记的事
- [ ] `data/persona_state_*.json` 生成且内容具体（不是"正在思考人生意义"这种概念化描述）
- [ ] 换了一天再聊，朋友的状态卡有更新，且和上次衔接得上

## 不要做

- 不要引入向量数据库/RAG 框架，事实库几十条用不上
- 不要做接话决策的模型化改造（那是群聊的事，本轮主线是 1 对 1）
- 不要加重生成/多轮校验的模型调用，先看便宜的改动能到什么程度
- 不要动记忆文件的隔离策略（群聊共享、1 对 1 按人设独立），那是已验证的决策
